# Задача для Codex: адаптировать Integration API к текущему GIS

Пакет передаётся без требования Git. Начни с этого файла, затем прочитай
INTEGRATION.md, REVIEW.md и VALIDATION.md. Это рабочая реализация для адаптации,
не подтверждённый production-релиз.

## Цель

Добавить серверный `/integration/v1` для backend ТехПортал PWA: чтение карт,
слоёв, объектов в bbox, карточки объекта и приём отчёта по выбранному объекту.
Токен хранится только на backend PWA. GIS остаётся владельцем сети и отчётов.
Пользователь PWA смотрит карту и отправляет отчёт при закрытии подключения.
Без выбранного `feature_id` отчёт недопустим.

## Порядок работы

1. Прочитай инструкции текущего проекта. Изучи актуальные маршруты, защиту,
   схему БД, фотоархив и доставку Telegram. Сохрани локальные изменения.
2. Сравни `baseline/` с текущими файлами. Baseline взят из предоставленного
   архива исходников, а не из upstream Git. Хеши — в MANIFEST.json.
3. Адаптируй новые файлы из `files/`. Не заменяй совпадающие по имени файлы
   без сравнения. `patches/existing-files.patch` показывает только три
   интеграционных изменения существующего проекта, не является командой
   для слепого применения. Полные целевые версии — в `reference/`.
4. Выполни подключение по INTEGRATION.md. Не переноси Docker-конфигурацию PWA,
   development-исключения или локальную БД. Новые зависимости не требуются.
5. Устрани несоответствия из REVIEW.md, синхронизируй OpenAPI с поведением
   и добавь интеграционные проверки из VALIDATION.md на изолированной БД.
6. Подготовь описание изменений, результаты команд и оставшиеся ограничения.
   Применение миграций в production и выдача настоящего токена — отдельная
   операция владельца GIS. Не публикуй секреты в ответах или файлах проекта.

## Границы

Не включать архив прежних фотоотчётов, просмотр фото и историю изменений:
это отдельный будущий план. Не открывать редактирование сети, удаление,
импорт/экспорт, UserSide или управление пользователями сервисному клиенту.
Не менять сценарии cookie-авторизации существующей карты GIS.

## Критерии готовности

Все маршруты требуют правильный Bearer; карта вне allowlist недоступна.
Повтор одного отчёта возвращает прежний результат; конкурентные повторы
создают одну запись и не дублируют Telegram-задание. Другие данные с тем же ID
дают 409. Сверка после потери ответа работает независимо от последующего
скрытия объекта. Файлы переживают пересоздание контейнера. Ошибки загрузки
не подтверждаются успешной квитанцией. OpenAPI соответствует фактическим ответам.
