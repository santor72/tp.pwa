# Проверки и порядок установки

Команды в корне GIS (использовать зависимости и версии текущего проекта):

```sh
bun run typecheck
bun test tests/integration-config.test.ts
bun run build
```

Prisma validate и migrate deploy запускать штатным CLI проекта с
`--config prisma.config.ts`. Сначала validate, затем миграция только на
изолированной тестовой БД; не использовать migrate reset в рабочем окружении.
Новые миграции до установки приложения; на откате приложения сохранять
квитанции и фото, не удалять таблицу с уже принятыми отчётами.

## Интеграционные тесты, которые надо добавить/выполнить

- Без токена, неверный/отозванный токен, карта вне allowlist, обычные cookie API.
- Maps/layers/bounds/viewport/search/details/assets; удалённый объект и слой.
- Корректный текстовый отчёт, каждый формат фото, отсутствие feature_id,
  неверный MIME/байты, чрезмерные размеры, пустой отчёт, запрещённая геометрия.
- Одинаковый повтор, конфликт метаданных/байтов/порядка фото, конкурентные POST:
  одна запись, одна квитанция, максимум одно задание Telegram.
- Потеря ответа после COMMIT, сверка, повтор после скрытия объекта;
  смена токена с прежним client_id сохраняет идемпотентность.
- Отказ диска/БД, частичная запись, неопределённый COMMIT, восстановление файлов.
- Валидация OpenAPI 3.1 и соответствие реальных JSON-ответов схемам.

Использовать тестовые UUID и временный фотоархив, Telegram заменить заглушкой.
Не отправлять сообщения реальным чатам и не создавать отчёты в рабочей БД.

Результаты реально выполненных проверок при упаковке лежат в validation.txt.
Они не заменяют перечисленные интеграционные тесты. Внешний PR не создавался:
upstream-репозитория у команды нет. Пакет предназначен для адаптации Codex.
