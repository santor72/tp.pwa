На этой станции приложение уже работает на порту 8081, а админка пока не запущена. Развернуть обновление можно так.

  ### 1. Разрешить вход в локальную админку

  В compose.yaml, в секции api → environment, замените ALLOWED_ORIGINS на:

  ALLOWED_ORIGINS: http://localhost:8081,http://127.0.0.1:8081,http://localhost:8082,http://127.0.0.1:8082

  Без этого вход через порт 8082 может завершиться ошибкой «Недопустимый источник запроса». Изменение только .env здесь не поможет: значение сейчас задано непосредственно в Compose.

  ### 2. Собрать новые образы

  В терминале:

  cd /home/santor/Документы/work/tp.pwa

  docker compose build migrate api payment-worker frontend admin-frontend

  Пока идёт сборка, существующее приложение продолжает работать.

  ### 3. Обновить базу данных

  docker compose run --rm migrate

  Команда применит миграции, включая таблицу замеров. Существующие платежи сохранятся. Если команда завершится с ошибкой — следующий шаг не выполняйте.

  ### 4. Обновить контейнеры

  docker compose up -d api payment-worker frontend admin-frontend
  docker compose ps

  Проверить сообщения об ошибках:

  docker compose logs --tail=100 api payment-worker admin-frontend

  Не используйте docker compose down -v: это удалит тома с данными.

  ### 5. Проверить результат

  Откройте на этой станции:

  - Приложение: http://localhost:8081 (http://localhost:8081)
  - Админка: http://localhost:8082/admin/ (http://localhost:8082/admin/)

  Обновите страницу приложения, чтобы загрузилась новая версия. В админку войдите пользователем ТП с ролью admin, затем откройте «Скорость формирования».

  Сформируйте новую оплату, дождитесь QR и нажмите «Обновить» в админке. Оплачивать её для проверки замеров необязательно.

  Учтите: локальное приложение использует Битрикс из вашего .env — формирование создаёт реальные CRM-сущности и может запустить отправку сообщения клиенту.
