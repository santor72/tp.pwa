# Карта mobilemap в PWA

PWA читает карты, слои, точки, карточки, значки и тайлы из отдельного mobilemap.
Исходные UUID сохраняются. Отчёты и фотографии по-прежнему отправляются в GIS:
`GIS_BASE_URL` и `GIS_API_TOKEN` менять на mobilemap нельзя.
Синхронизация источника, классификация и генерация тайлов остаются у оператора mobilemap.

## Подключение на одном сервере

1. Создать сеть: `docker network create tp-mobilemap` (один раз).
2. В mobilemap использовать `docker-compose.pwa.yml` вместе с основным Compose:
   `docker compose -f docker-compose.yml -f docker-compose.pwa.yml up -d api`.
   Этот override снимает публикацию API-порта и добавляет псевдоним `mobilemap-api`.
   Обоим API нельзя давать общее имя `api` в настройке соединения.
3. В окружении PWA задать `MAP_SOURCE=mobilemap`,
   `MOBILEMAP_BASE_URL=http://mobilemap-api:8000`,
   `MOBILEMAP_USERNAME` и `MOBILEMAP_PASSWORD` из настроек Basic Auth источника.
   Пароли не коммитить. `MOBILEMAP_TIMEOUT_SECONDS` по умолчанию 20.
4. Собрать и запустить PWA с дополнительным override:
   `docker compose -f compose.yaml -f compose.mobilemap.yaml up -d --build --no-deps api frontend`.
   При использовании других production override сохранить их в команде.
5. При следующих перезапусках также включать `compose.mobilemap.yaml`.

В источнике ожидается `MAP_PROVIDER=yandex21`, `DATA_SOURCE=postgis`,
`LINE_RENDER=raster` и опубликованная версия тайлов. Сервис может работать отдельно
от PWA. Его PostGIS остаётся в собственной сети.
Отдельный веб-интерфейс mobilemap и опубликованный порт его БД не нужны PWA;
оператор управляет доступом к ним отдельно.

## Поведение

- Оба сценария PWA используют один компонент: экран карты и выбор объекта заявки.
- Районные слои фильтруют точки. Пустой набор скрывает все точки.
- Линии переключаются отдельно: «Сеть (линии)» и «Линии столбов».
  По умолчанию включена сеть; предпочтения хранятся для каждой карты.
- Версия тайлов запрашивается при открытии, смене карты и возвращении из фона.
  При смене версии растровые слои пересоздаются.
- Размеры точек берутся из конфигурации mobilemap. Все отображаемые точки
  кликабельны на любом масштабе независимо от `GIS_POINT_DETAIL_ZOOM`.
- При прореживании показывается уведомление о частичной выборке.
- Отсутствие тайлов или недоступность источника не запускает синхронизацию
  и не переключает источник автоматически.

## Доступ и кэш

Все маршруты `/api/mobilemap/*` требуют действующую сессию и доступ к данным карты
(включая отдельное право выбора объекта в заявке). Basic Auth добавляет backend.
Маршруты sync не проксируются. Ошибка учётных данных сервиса возвращается как 502,
а не как 401 пользовательской сессии.
Метаданные не кэшируются HTTP-кэшем. PNG/WebP используют `private, no-cache` и ETag:
перед повторным использованием проверяется сессия, затем актуальное изображение.
Service worker не получает правила офлайн-кэширования API.

## Откат

Установить `MAP_SOURCE=gis`, пересоздать API с тем же набором Compose-файлов,
перезагрузить страницу PWA. Исходные GIS-настройки и прежние рендереры сохранены.

## Проверки реализации

- `cd backend && PYTHONPATH=. .venv/bin/pytest tests/test_mobilemap.py tests/test_gis_routes.py tests/test_gis_client.py tests/test_capabilities.py tests/test_completion_routes.py tests/test_completion_service.py -q`
- `npm test --prefix frontend`
- `npm run build --prefix frontend`

Компонентные тесты проходят оба сценария с имитацией SDK Яндекса: загрузка карты,
открытие карточки, выбор объекта для заявки и отправка отчёта из карты. Отдельный
тест проверяет проекцию, Retina URL, смену версии и отключение растровых слоёв.
Для приёмки на телефоне дополнительно проверить реальный SDK и ощущения при
движении/масштабировании; компонентные тесты не измеряют FPS и мобильную память.
