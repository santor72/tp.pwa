# Переход карты PWA на Яндекс API 2.1

Статус: согласованный план, реализация не начата.

Использовать один картографический движок Яндекса с двумя подложками — **«Схема» и «Гибрид»**. Сохранить отображение объектов GIS и текущие пользовательские сценарии. Выбор подложки запоминать на клиенте. Редактор геометрии не добавлять.

## Этап 1. Настройка подключения

- Добавить серверную переменную `YANDEX_MAPS_API_KEY`, описание в примере окружения и передачу в API-контейнер.
- Добавить `GET /api/gis/basemap` с существующей проверкой доступа к GIS. Ответ: `{ scriptUrl: string | null }`, без кэширования. При отсутствии ключа возвращать `null`; остальные функции приложения остаются доступны.
- Формировать адрес официального SDK 2.1.79 с русским языком и режимом CSP, как в проверяемой реализации `tochka-gis`.
- Ключ хранить в окружении сервера; браузер получает его в адресе SDK. Настроить разрешённые домены PWA в кабинете Яндекса.
- Проверить ограничения CSP на фактическом сервере и разрешить необходимые ресурсы Яндекса, если ограничения установлены.

**Результат:** PWA получает параметры подключения через собственный backend, ключ не зашит в исходники или сборку frontend.

## Этап 2. Общий компонент карты

- Вынести реализацию карты из `App.tsx` в отдельный компонент, сохранив интерфейс передачи объектов, положения карты, геолокации и обработчиков.
- Создать общий загрузчик SDK: один запрос загрузки для обоих экранов, ожидание готовности, тайм-аут 20 секунд и возможность повторить попытку.
- Создавать карту при открытии компонента; при закрытии уничтожать экземпляр и освобождать обработчики.
- Перенести масштабирование, перемещение, показ загруженных объектов, геолокацию и полноэкранный режим.
- Пересчитывать размер карты при изменении высоты, открытии окна выбора объекта и переходе в полный экран.
- Сохранить видимость и доступность атрибуции Яндекса.

**Результат:** карта работает на основном экране GIS и в выборе объекта для заявки.

## Этап 3. Объекты GIS и взаимодействие

- Отображать точки через собственные маркеры Яндекса, используя существующие PNG из `/api/gis/assets/{iconId}`.
- Сохранить прозрачность, размер `iconScale`, серверное перекрашивание, привязку изображения к центру точки и круглый маркер под PNG.
- Сохранить варианты точек без PNG: круг и значок с остриём.
- Перенести линии и полигоны с их цветами, толщиной, прозрачностью и внутренними контурами.
- Нажатия связывать с существующими карточками и выбором объекта в заявке.
- Явно преобразовывать порядок координат между GeoJSON `[долгота, широта]` и стандартным порядком API 2.1 `[широта, долгота]`.
- Сохранить запросы объектов по видимой области и существующую задержку 250 мс. Обновление данных и геолокации не должно пересоздавать карту.
- Сохранить запоминание центра и масштаба в `sessionStorage`.

**Результат:** объекты визуально совпадают с текущими, карточки и привязка к заявке работают.

## Этап 4. Подложки и localStorage

- Оставить два режима: `map` → `yandex#map`, `hybrid` → `yandex#hybrid`.
- Использовать ключ **`tp-pwa.gis.basemap`**, общий для основной карты и выбора объекта.
- При открытии читать сохранённое значение; по умолчанию и при некорректном значении использовать `map`.
- Сохранять новый выбор после успешного переключения. На время переключения блокировать повторное действие; при ошибке оставлять предыдущий режим.
- При недоступном `localStorage` сохранять работоспособность переключателя в текущем сеансе.
- При переключении сохранять центр, масштаб, объекты и открытую карточку.

**Результат:** выбранная подложка восстанавливается после закрытия карты, обновления страницы и перезапуска PWA.

## Этап 5. Ошибки и завершение интеграции

- Показывать состояния загрузки, отсутствующего ключа и ошибки SDK с кнопкой повторной загрузки.
- Не переключаться автоматически на стороннюю подложку или прямые недокументированные адреса тайлов.
- Удалить зависимости Leaflet, его CSS и старые реализации подложек после переноса обоих экранов.
- Не добавлять кэширование ресурсов Яндекса в service worker.
- Обновить документацию настройки ключа и проверки новой версии PWA.

**Результат:** приложение использует только Яндекс для карты; ошибки загрузки обрабатываются явно.

## Этап 6. Проверки и выпуск

- Автоматически проверить сохранение и восстановление подложки, повреждённое значение и недоступность `localStorage`.
- Проверить преобразование координат и границ области, выбор объектов, повторное открытие карты и очистку обработчиков.
- Адаптировать существующие тесты, привязанные к DOM Leaflet, к пользовательскому поведению нового компонента.
- Проверить доступ к новому endpoint, ответ без ключа и повторную загрузку после ошибки.
- Выполнить сборку и frontend-тесты, а также backend-тесты затронутых GIS-маршрутов.
- В браузере с действующим ключом проверить обе подложки, PNG и перекрашивание, линии, полигоны, геолокацию, полный экран и оба сценария выбора объекта.
- На телефоне и в установленной PWA проверить жесты, попадание по значкам, восстановление подложки и плавность работы на реальных данных.
- Выпускать после проверки ключа и доменных ограничений. Сохранить предыдущую сборку для отката и проверить обновление установленной PWA.

**Критерий готовности:** оба экрана работают на Яндексе, схема и гибрид переключаются без потери состояния, выбор восстанавливается, PNG-значки и существующие действия с объектами сохранены.

Данные GIS, база и интеграция отчётов остаются в существующей архитектуре; миграция данных не требуется. Подключение реального ключа и проверка разрешённых доменов — обязательные условия проверки перед выпуском.
