# План реализации Telegram и подсистемы мессенджеров

## Как работать с этим планом

Это рабочий план агента для последовательной реализации. Перед каждым этапом нужно:

1. проверить текущие изменения рабочего дерева и не затирать их;
2. прочитать [архитектурное решение](messengers-architecture.md);
3. выполнять этап целиком вместе с тестами и документацией;
4. не переходить дальше, пока не выполнены критерии готовности;
5. после проверки отмечать чекбоксы и фиксировать существенные отклонения в
   архитектурном документе.

Каждый этап должен оставлять проект в запускаемом и тестируемом состоянии.

Критерий: известны bot username, тестовые группы и реальные chat ID; секрет не
записан в репозиторий.

## Порядок первого рабочего релиза

Первый вертикальный срез завершается раньше полного Telegram UI:

1. этапы 0–4: PostgreSQL, пользователи, токены и общие границы;
2. этап 5: PWA умеет создать deep-link;
3. этапы 6–8: bot polling, access middleware и привязка;
4. минимальный handler «показать количество заявок на сегодня»;
5. integration test полного пути.

После этого добавляются полные заявки, изменение статуса и Домофон. Этот порядок рано
проверяет самые рискованные части: БД, два процесса, Telegram access и атомарную привязку.
