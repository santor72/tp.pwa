# PR: добавить Integration API v1 для ТехПортал PWA

## Проблема

Точка GIS предоставляет защищённый API для собственной браузерной карты через
cookie-сессию. Сервер ТехПортал PWA не может безопасно использовать эти маршруты:
ему нужны ограниченное чтение опубликованной сети и идемпотентная передача
фотоотчёта по выбранному объекту при закрытии подключения.

## Изменение

Добавлен `/integration/v1`, который принимает только `Authorization: Bearer`:

- карты, слои, GeoJSON области, поиск, карточки и значки;
- `POST /integration/v1/reports` с обязательным `feature_id`, внешним автором,
  идентификаторами заявки/операции и до пятью проверенными фотографиями;
- проверка квитанции по внешнему ID после потери HTTP-ответа;
- migration `integration_report_receipts`, гарантирующая ровно один отчёт на
  `(client_id, external_report_id)` и конфликт при другом содержимом;
- OpenAPI: `/integration/v1/openapi.json`;
- полные OpenAPI-схемы для DTO, multipart-отчёта и ошибок, включая контракт
  идемпотентного повтора;
- allowlist карт (`GIS_INTEGRATION_MAP_IDS`) и отдельный сервисный токен.

Интеграция не даёт доступа к существующим `/api/*`, экспорту, импорту,
редактированию объектов или управлению пользователями. В production нужен
непустой allowlist карт. Токен не включается в OpenAPI, ответы или логи.

## Настройка

```text
GIS_INTEGRATION_CLIENT_ID=tp-pwa
GIS_INTEGRATION_TOKEN_SHA256=<SHA-256 случайного секрета>
GIS_INTEGRATION_MAP_IDS=<uuid-карты-1>,<uuid-карты-2>
GIS_INTEGRATION_REPORT_GEOMETRY_TYPES=Point,LineString
GIS_INTEGRATION_PHOTO_RETENTION_DAYS=365
```

Исходный секрет выдаётся владельцу PWA вне Git, в GIS записывается только его
SHA-256. При замене старый токен отзывается до включения нового. Перед установкой применить Prisma migration, после установки
проверить токен и allowlist тестовым запросом `GET /integration/v1/maps`.

Контракт отчёта: до 5 файлов JPEG, PNG или WebP, не более 10 MiB каждый;
файл проверяется по содержимому, а не по расширению. По умолчанию отчёт можно
создать только для `Point` и `LineString`; `Polygon` включается только явной
настройкой. В квитанции хранится и возвращается `retention_until`; это дата
минимального хранения фото. Удаление после неё — отдельная регламентная задача
архива, а не побочный эффект API-запроса.

## Проверки

В данном checkout выполнены:

```text
npx bun test tests/integration-config.test.ts
npx bun run typecheck
```

Результат: 4 теста проходят, TypeScript typecheck проходит.

Перед merge нужны интеграционные проверки с тестовой БД: отсутствие/неверный/
отозванный токен, карта вне allowlist, запросы GeoJSON и поиск, неверный объект,
неверные фотографии, одинаковый и конкурентный повтор отчёта, потеря ответа после
COMMIT и единственность Telegram-задания.

## Статус передачи

Исходный каталог `tochka-gis/current` не содержит `.git` и его операционные
журналы подтверждают отсутствие внешнего Git remote. Поэтому это готовое
содержание PR, но не опубликованный pull request. Для публикации нужен URL
upstream и доступ на создание ветки/PR; текущая реализация не создаёт фиктивный
remote или PR в чужом репозитории.
