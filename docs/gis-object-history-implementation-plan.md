# Просмотр истории объекта GIS: план реализации

Дата: 16.09.2026. Статус: запланировано; пункты ниже ещё не выполнены.
Основание: [архитектура просмотра истории](gis-object-history-architecture.md).
Это самостоятельное расширение карточки, не блокирующее отправку отчётов
при закрытии подключения из основного этапа 3.

## 1. Контракт и тестовые данные

- [ ] Подтвердить доступ пользователей PWA ко всем прежним отчётам опубликованных карт.
- [ ] Зафиксировать DTO, 20 записей на страницу, курсор, порядок, даты и авторство
  старых и внешних отчётов; описать ошибки 400/401/404/503 и условие для 410.
- [ ] Проверить архив: постоянное хранение файлов, соответствие ссылок БД,
  реальные MIME/размеры старых фото и резервное восстановление.
- [ ] Подготовить изолированные фикстуры: обычный и внешний отчёт, отсутствие
  автора/времени события, несколько страниц, фото разных форматов, потерянный файл.
- [ ] Согласовать upstream GIS и ветку PR; исходники GIS не включать в PWA.

Результат: проверяемый контракт и набор данных для обеих сторон.

## 2. PR GIS: чтение отчётов и фотографий

- [ ] Реализовать два GET-маршрута Integration API из архитектуры.
- [ ] Проверять Bearer, публикацию карты, активный объект/слой и принадлежность
  отчёта/фото; валидировать курсор в контексте конкретного объекта.
- [ ] Формировать ограниченные DTO, не возвращать сырые `attachments`.
- [ ] Сохранять различие времени события и добавления, нормализовать даты с timezone.
- [ ] Выдавать фотографии безопасным потоком с установленными заголовками.
- [ ] Обновить OpenAPI полными схемами, параметрами, примерами и ошибками.
- [ ] Проверить неверный токен, чужую карту/объект/фото, удалённый слой,
  неверный курсор, одинаковые timestamps, конкурентное добавление отчётов,
  отсутствующие файлы и неизменность существующего браузерного API GIS.
- [ ] Подготовить PR и инструкцию деплоя; опубликовать при наличии upstream/доступа.

Результат: read-only API развёрнут в тестовом GIS; проверки не создают рабочие отчёты.

## 3. Backend PWA

- [ ] Добавить методы адаптера и session-protected маршруты `/api/gis/*`.
- [ ] Реализовать поток фото с тайм-аутами, лимитом байтов, MIME-проверкой,
  закрытием потока при отключении клиента и запретом произвольных URL/редиректов.
- [ ] Нормализовать ошибки без утечки токена и внутренних путей GIS.
- [ ] Добавить отдельный флаг доступности архива и передавать его frontend.
- [ ] Проверить отсутствие сессии, ошибку токена GIS, тайм-ауты, 404/503,
  чрезмерный поток без Content-Length, неверный MIME и отмену скачивания.

Результат: браузер получает историю и фото только через backend PWA.

## 4. Карточка и архив PWA

- [ ] Добавить «Отчёты и фотографии» и ленивую загрузку первой страницы.
- [ ] Показывать автора, время добавления, отдельно время события, текст,
  отметку заполнения при наличии и фотографии выбранного отчёта.
- [ ] Реализовать пагинацию, пустое состояние, повтор после ошибки и увеличение фото.
- [ ] Отменять устаревшие запросы; не допускать подмены карточки при быстром выборе.
- [ ] Обеспечить клавиатуру, Escape, управление фокусом и мобильную компоновку.
- [ ] Исключить историю и фото из offline-кэша; безопасно отображать текст.
- [ ] Проверить загрузку по требованию, перелистывание, смену объекта, отказ
  отдельного фото, завершение сессии и неизменность поведения карты.

Результат: пользователь читает прежние отчёты и фотографии в карточке объекта.

## 5. Опционально: история изменений

- [ ] Подтвердить потребность и перечень доступных полей изменений.
- [ ] Добавить пагинированный GET `/integration/v1/features/{id}/revisions`,
  фильтрацию служебных полей и OpenAPI; затем соответствующий backend-маршрут.
- [ ] Добавить отдельную возможность/флаг и раздел «История изменений» в карточке.
- [ ] Проверить человеческое/системное/неизвестное авторство, безопасное
  отображение «было/стало», пагинацию и отсутствие приватных полей.

Результат: история доступна только при включении; её отсутствие не мешает архиву отчётов.

## 6. Сквозная приёмка и включение

- [ ] Выполнить сценарий PWA → backend → GIS на изолированной БД и фотоархиве:
  обычный и внешний отчёт, две страницы, просмотр каждого поддерживаемого формата.
- [ ] Проверить отказ для недоступных объектов и чужих UUID, поведение при сбоях GIS,
  отсутствие API-токена в браузере и фотографий в Service Worker-кэше.
- [ ] Проверить сохранность фото после пересоздания GIS-контейнера и восстановление
  согласованной пары БД/файлов из резервной копии в тестовой среде.
- [ ] Убедиться, что просмотр не создаёт записи, Telegram-задания или изменения заявки.
- [ ] Обновить инструкцию пользователя и эксплуатационные заметки; зафиксировать
  результаты приёмки, ссылку на GIS PR и установленную версию.
- [ ] Включить архив после деплоя GIS и backend; проверить отключение флагом
  без нарушения карты и отправки отчёта подключения.

Критерий завершения: архив доступен из карточки, авторство и даты достоверно
отражают данные GIS, фотографии загружаются только по защищённым маршрутам,
а ошибки и пагинация проверены сквозными тестами. Опциональный пункт 5
не входит в обязательный критерий до подтверждения его необходимости.
