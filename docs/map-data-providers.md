# Провайдеры данных карты

Frontend использует два независимых контракта:

- `GisMapCanvas` — отображение объектов (Яндекс Карты 2.1 или v3).
- `MapDataProvider` — чтение карт, слоёв, границ, объектов области и карточки объекта.

`frontend/src/MapDataProvider.ts` определяет модель данных и интерфейс чтения.
Координаты идут в порядке longitude/latitude, границы — west/south/east/north.
Идентификаторы считаются непрозрачными строками. Список объектов — полный снимок
запрошенной области, с признаком `truncated` и лимитом `limit`. Пустой список
слоёв означает все слои. Каждый метод принимает необязательный `AbortSignal`;
ошибки и отмена передаются вызывающему коду через отклонённый Promise.

`GisDataProvider.ts` реализует контракт через защищённый `/api/gis` backend PWA.
Адаптер снимает оболочку `rows`, преобразует границы в общий формат, нормализует
масштаб запроса и формирует готовый `iconUrl`. Провайдеры отображения не знают
маршрутов GIS и формата идентификаторов значков. Общий HTTP-клиент `http.ts`
сохраняет обработку cookies, истечения сессии и ошибок API.

Выбор источника выполняется в `selectedMapDataProvider.ts`. Чтобы подключить
другой источник, реализуйте `MapDataProvider` и поменяйте выбранную реализацию
в этом файле. Экран карты и выбор объекта в заявке используют один провайдер.
Выбор движка отображения выполняется отдельно в `ProviderMapCanvas.tsx`.

Задержка запросов, отмена устаревших загрузок и состояние интерфейса остаются
в компонентах. Настройки подложки относятся к движку отображения. Отправка
отчётов и закрытие заявок остаются отдельными операциями `api.ts`: контракт
чтения не обещает поддержку записи другим источником данных.

Этот слой не добавляет кэширование, офлайн-хранилище или подписку на изменения.
Серверная интеграция и проверки доступа сохраняются.
